# Development Best Practices Directive

When implementing any feature or code component:

## 1. Research Phase

- **Search for latest best practices** using web search or Context7 MCP for documentation
- **Review open source implementations** on GitHub for similar patterns
- **Consult official documentation** for frameworks and libraries being used
- **Check for design patterns** that apply to the problem domain

## 2. Task Breakdown

- **Break complex tasks into atomic sub-tasks** (max 1-2 hour implementation each)
- **Identify dependencies** between sub-tasks
- **Create testable units** - each sub-task should be independently verifiable
- **Document assumptions** that need validation

## 3. Implementation Standards

- **Follow language-specific style guides** (PEP8 for Python, Airbnb for JS/TS)
- **Write tests alongside code** (TDD when appropriate)
- **Use type hints/annotations** for all function signatures
- **Add docstrings/JSDoc** for public interfaces
- **Handle errors gracefully** with proper logging

## 4. Verification

- **Run existing tests** to ensure no regressions
- **Add unit tests** for new functionality
- **Verify integration** with existing systems
- **Document any API changes**
